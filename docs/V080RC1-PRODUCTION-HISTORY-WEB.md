# HRM v0.8.0-rc.1 — Production History + Linux Web Test

## Release purpose

This candidate extends the tested v0.7.0-rc.1 Windows baseline without replacing its security,
installer, migration, backup, TLS, audit or protected-real-data contracts. The Windows desktop
application remains the primary organizational deployment target. The Linux Web package is an
explicit test surface and is labelled **NOT FOR PRODUCTION**.

## Personnel movement model

For an existing personnel record, changes to organizational unit, position code/title, actual
location and employment/service status must be performed through a personnel movement event.
The normal personnel edit route rejects attempts to change those fields directly.

A movement records:

- movement type;
- effective date;
- order number and order date;
- reason and note;
- before/after personnel snapshots;
- previous and new assignment identifiers;
- creator and creation time;
- reversal metadata when applicable.

The current assignment is closed at the effective date and retained. A new assignment is then
created. The movement and the personnel projection are both written to the tamper-evident audit
chain. Optimistic `row_version` checking prevents stale clients from silently overwriting a
newer personnel state.

Supported movement types are appointment, transfer, position change, unit change, location
change, acting assignment, retirement, service exit, service return, correction and other.

Only the latest active movement can be reversed. Reversal preserves the movement event and
restores the previous assignment/state rather than deleting history.

## Organizational roles

`owner` is the **Super Admin** role. It retains all permissions including user/security
administration, hard delete, restore and movement reversal.

`admin` is the **HR Admin** role. It can perform normal HR work including personnel edits,
personnel movements, audit viewing, workflow work and backup creation, but cannot hard-delete,
restore, change users/security or reverse a movement.

The intended initial deployment is 2 Super Admin + 4 HR Admin.

## Windows organizational build

The Windows package remains native PySide6 client/server software for Windows Server 2022 and
internal LAN clients. The desktop personnel page exposes movement registration and movement
history. Organizational fields are read-only in the ordinary edit dialog for existing people.

GitHub Windows acceptance must prove the existing install/service/TLS/backup/real-data gates and
a real in-place upgrade from the exact tested v0.7.0-rc.1 source baseline to v0.8.0-rc.1.

## Linux Web Test

The Linux test package uses the same Python backend, database schema, migrations, permissions and
movement API. It does not duplicate HR business rules in a second backend. Static browser assets
are served same-origin by the HRM server.

The Docker test surface intentionally uses HTTP bound to loopback by default and is marked test
only. It must not be exposed as a production organizational service without a separate security
and operational release review.

Run from the extracted Linux package with the supplied `deploy/linux-web-test/start.sh`, or build
with the supplied Dockerfile/Compose definition. The first password is locally generated by the
start script and must be changed on first login.

## Data/privacy boundary

No raw Excel/CSV HR dataset, plaintext decrypted bundle, operational database, Fernet key or local
`.env` file belongs in public CI artifacts. Protected real-data validation emits aggregate-only
evidence under the existing organization contract: 1356 personnel, 590 enrichments, 185 active
named assignments, 568 approved chart posts (536 fixed + 32 named), page 16 total 24, one ignored
legacy row.
