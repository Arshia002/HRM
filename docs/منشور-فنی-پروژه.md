# منشور فنی و روش همکاری پروژه HRM

## مسئولیت‌ها

- مدیر پروژه: تعیین اولویت‌های محصول، نیازهای سازمان، دامنه هر نسخه و تأیید پذیرش.
- مدیر فنی: معماری، امنیت، کیفیت کد، طراحی Build، تست، مستندسازی فنی و مدیریت ریسک.
- تصمیم انتشار: پس از مشاهده نتیجه تست‌ها و با تأیید مشترک مدیر پروژه و مدیر فنی.

## اصول ثابت

1. `main` باید همیشه قابل Build و قابل ردیابی باشد.
2. هر تغییر مهم با Branch کوتاه‌مدت، تست و بازبینی وارد `main` می‌شود.
3. هیچ داده واقعی پرسنلی، رمز، کلید خصوصی، Backup یا دیتابیس عملیاتی وارد Git نمی‌شود.
4. هر خروجی Windows دارای نسخه، Manifest ساخت، فهرست وابستگی‌ها و SHA-256 است.
5. Setup فقط زمانی قابل تحویل است که Build، نصب Silent، ارتقا، سرویس، TLS و حذف آن در Windows CI سبز باشند.
6. داده عملیاتی هنگام ارتقا یا Uninstall حذف یا جایگزین نمی‌شود.
7. تصمیم‌های کوتاه‌مدت نباید امنیت، نگهداری‌پذیری و قابلیت توسعه محصول را قربانی کنند.

## هدف نسخه 0.1.0-alpha.2

یک Setup آزمایشی مستقل برای Windows x64 با سه حالت نصب «کامل»، «سرور» و «کلاینت» که:

- کلاینت بومی Qt را بدون مرورگر و بدون وابستگی Runtime خارجی اجرا کند؛
- سرویس مرکزی را روی شبکه داخلی نصب و راه‌اندازی کند؛
- دیتابیس مرکزی، حساب مالک اولیه، TLS، Audit و همگام‌سازی شش مدیر را فراهم کند؛
- با دیتای ساختگی امن Build شود؛
- نصب، ارتقای درجا، حفظ داده و Uninstall آن به‌صورت خودکار تست شود.

این نسخه معیار تأیید زیرساخت نصب و شبکه است. دیتای واقعی و بازسازی کامل رابط نسخه 4.9 پس از تأیید این مرحله وارد مسیر توسعه می‌شوند.

## تعریف «انجام‌شده»

یک قابلیت زمانی انجام‌شده است که کد، تست، مستندات لازم و معیار پذیرش آن کامل باشد؛ Build ویندوز سبز شود؛ و مدیر پروژه خروجی قابل نصب را روی سیستم آزمایشی تأیید کند.
